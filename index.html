Your apps, your server.
No sysadmin needed.

Deploy Boat turns a cheap VPS into your own little Heroku. Publish anything with one command, from Git, or by telling your AI agent to publish it.

Install on your server
$curl -fsSL deployboat.github.io/install.sh | sudo bash

Run it on a fresh Ubuntu or Debian server. A few minutes later you have a dashboard. Free and open source (MIT).

Why I made this

I kept building small apps, some of them with an AI agent, and every one ended up on a different platform with its own bill. Self-hosting tools could fix that, but they wanted me to learn a lot of settings first.

So I built the version I wanted: install it once, then publishing is one command. A database when an app needs one. Backups that happen by themselves. A server that tells me in plain words when something's wrong, and usually fixes it.

If it saves you the same headaches, that's the whole point.

Three ways to publish

No Dockerfile, no YAML. It figures out what you built: plain HTML, React, Next.js, Node, Python, Go, PHP and more.

01

From your terminal

Run one command in any project folder. Run it again to publish an update.

npx deployboat deploy
02

From Git

Connect a GitHub, GitLab or Gitea repo. Every push goes live, and pull requests get a preview.

git push origin main
03

From your AI agent

Connect it once, then ask. It deploys, reads the logs and fixes what broke.

“publish it”
~/shop $ npx deployboat deploy --with database
→ Uploading shop…
→ Building (Next.js)
→ Creating your database…
✓ Live: https://shop.1.2.3.4.nip.io

You won't need the docs

There's no manual to read first. The dashboard explains each thing right when you get to it, in plain words, with your own details already filled in. If something goes wrong, it tells you what happened and what to do next.

When you add your own domain
Add an A record where you bought the domain: name @, value 1.2.3.4. The status turns to Connected by itself.
When a deploy fails
We couldn't build your project. Tip: a Node app needs a package.json with a "start" script.
When you connect a Git repo
Where do I paste it? GitHub: repo → Settings → Webhooks → Add webhook. Choose Pushes and Pull requests.
When you set up backups
Six short steps, each with a direct link:
  1. Create a project in Google Cloud
  2. Turn on the Drive API
  3. …

Your AI agent gets the same help: it can ask Deploy Boat how apps should be built before it writes a line.

Made for building with AI

Deploy Boat comes with an MCP server, so Claude Code, Cursor and other agents get real tools instead of guessing shell commands. They can deploy, add a database, read logs and save API keys you give them.

Agents get their own limited token. They can publish and debug, but they can't delete apps, change the server or read your secrets.

you:   publish this, it needs a database
agent: deploy(services: ["database"])
agent: the build failed: no start script. Fixing package.json…
agent: deploy()
✓ Live: https://shop.1.2.3.4.nip.io

Data

Every night, with a copy in Google Drive or S3.

Email

Running it

Scheduled jobs
Call a URL or run a command, with retries.
Versions
Every deploy is kept. Roll back in one click.
Monitoring
Uptime, response times, CPU and memory history.

A server that looks after itself

The installer locks the server down on day one: firewall, protection against password guessing, automatic security updates. After that, Server Doctor keeps checking around 40 things and tells you in plain words when something needs attention. Most problems come with a fix that explains exactly what it will do before it does it.

Disk is 92% full
SSH still allows password login
Backups only exist on this server
HTTPS certificates are validOK

What it looks like in the dashboard. Click a button.

Alerts can go to email, Discord, Slack or Telegram, so you don't have to keep the dashboard open.

Questions

Do I need to know Docker or Linux?

No. Docker runs under the hood and the server looks after itself. You use the dashboard, one command, or your AI agent.

Do I need a domain?

No. Every app gets a free HTTPS address straight away. Add your own domain whenever you want.

What kind of server?

Ubuntu 22.04 / 24.04 or Debian 12, with 1 GB of memory and 5 GB of disk. Any cheap VPS works: Hetzner, DigitalOcean, Vultr, Linode…

Is it really free?

Yes, MIT licensed. You only pay for the server.

Is it ready for production?

It's young and changes quickly, but it runs on real servers today. Turn on off-server backups first for anything you care about.

Something didn't work.

Please open an issue. Reports about anything confusing are just as welcome as bugs.
